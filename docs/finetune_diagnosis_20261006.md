## 已核对的输入、评估和训练协议

- 归档中的配置、训练器、评估器与本地对应文件一致。
- Pi0.5 两次评估的 seed 列表、20 Hz、750 步上限、每 5 步重新推理、50 步预测长度、任务指令一致。
- 相同 seed/config 是配对协议；未保存完整初始仿真状态哈希，尚不能证明逐数值完全相同。
- 三路相机均参与训练；未发现相机映射、RGB/BGR 或 state 排列错误。
- 训练与最终评估保留原始 normalization；最终 norm_stats 与原始文件逐字节一致：
  SHA256 4aed1af411bd0e0f49d2b0e6d6832b11b8682917231a07173fbc30fd493bbdee。
- 原始 20 fps，共 28 条、5916 帧；预处理记录保留原始帧序，动作值直接复制。
  这些检查不能代替原始演示动作语义和闭环回放的完整验证。
- Pi0.5：batch 4、10000 updates、peak LR 1e-5、warmup 500、cosine 到 1e-6；无 EMA。
- 40000 个训练窗口起点，约为 5916 个帧起点的 6.76 次平均遍历。
  因窗口重叠及轨迹相关性，不能把它当 40000 条独立经验；也不能把 10000 步说成几千个 epoch。
- 训练损失窗口均值从前 500 步约 0.0679 降至最后 2500 步约 0.0187；
  没有独立验证损失或中途闭环成功率，无法据此判定过拟合或选择最佳步数。
- 两次训练都是只用这 28 条继续训练，没有混入原始预训练数据。
- pretrained human300 的任务注册包含 OpenDrawer。Vanilla 已有此任务经验；
  这 28 条与预训练数据是否有具体 episode 重合，尚未核实。
- 演示原始图像 128×128，上采样到 256；评估直接渲染 256。
  这是已确认的输入清晰度差异，其性能影响尚未通过对照实验确认。
- Pi0.5 两组 clipping 的绝大多数在 gripper/control_mode 维度，
  不能把日志中很大的 clipped_count 直接理解成末端位置动作爆炸。

## 当前解释及不能下的结论

最值得排查的共同问题是：强预训练模型只在小范围演示分布上继续优化，
但实验没有独立验证集和中途闭环评估来判断修改是否改善目标测试分布。
这会允许行为偏移或遗忘，也可能和源图像清晰度、动作/状态语义差异共同作用。
目前没有证据锁定一个共同实现 bug。

不能确认“就是过拟合”“就是学习率太高”“就是 batch 太小”。
28 条较少并不保证微调影响较小；LoRA 也不提供保性能保证。
DP 与 Pi0.5 更新范围不同，不能用同一个未经验证的解释覆盖两次实验。
